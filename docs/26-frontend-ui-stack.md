# Frontend UI Stack

This document describes the UI libraries in use, why they were chosen,
how to add new components, and the conventions all frontend code follows.

Related: [16-frontend-folder-structure.md](16-frontend-folder-structure.md)

---

## Libraries

| Library               | Version      | Purpose                                                    | Docs                                                 |
| --------------------- | ------------ | ---------------------------------------------------------- | ---------------------------------------------------- |
| **Tailwind CSS v4**   | 4.x          | Utility-first CSS framework                                | https://tailwindcss.com/docs                         |
| **@tailwindcss/vite** | —            | Vite plugin (replaces PostCSS config)                      | https://tailwindcss.com/docs/installation/using-vite |
| **shadcn-vue**        | latest       | Copy-paste component library built on Tailwind + Radix Vue | https://www.shadcn-vue.com                           |
| **Radix Vue**         | (transitive) | Headless accessible primitives (used by shadcn-vue)        | https://www.radix-vue.com                            |

**Not in use**: Vuetify, Quasar, PrimeVue, Nuxt UI (Nuxt-specific — requires Nuxt framework).

---

## Why these choices

### Tailwind CSS v4

- Utility classes replace per-component `<style scoped>` blocks — less CSS to maintain.
- v4 uses `@import "tailwindcss"` in CSS and a Vite plugin instead of a `tailwind.config.js` file.
- Design tokens (colors, radius, etc.) live as CSS custom properties in `src/style.css`, generated by shadcn-vue init.

### shadcn-vue (not a package dependency)

shadcn-vue is **not installed as a node_modules package**. The CLI copies
component source files directly into `src/components/ui/`. You own the code —
customise freely without fighting an upstream API.

This means:

- components live in `src/components/ui/<name>/`
- they are plain `.vue` files — readable, editable, version-controlled
- upgrading a component = re-run the add command (it will ask to overwrite)

## Configuration files

| File                | What it does                                                                                     |
| ------------------- | ------------------------------------------------------------------------------------------------ |
| `src/style.css`     | `@import "tailwindcss"` + CSS variables generated by shadcn-vue init (colors, radius, dark mode) |
| `vite.config.ts`    | `tailwindcss()` Vite plugin + `@` alias pointing to `src/`                                       |
| `tsconfig.app.json` | `paths: { "@/*": ["./src/*"] }` — resolves `@/` imports in TypeScript                            |
| `components.json`   | shadcn-vue project config (style, icon library, component output path)                           |

---

## Path alias

All project imports use `@/` as the `src/` root:

```ts
import { Button } from "@/components/ui/button";
import { useAuthStore } from "@/stores/authStore";
```

This is configured in `vite.config.ts` (`resolve.alias`) and `tsconfig.app.json` (`paths`).
Never use relative `../` imports in views or components.

## Design tokens

shadcn-vue generates CSS custom properties in `src/style.css` using the
`@theme inline` block. Key tokens:

```css
--color-primary          /* main brand colour (buttons, links) */
--color-muted-foreground /* secondary text */
--color-border           /* card/input borders */
--color-destructive      /* error states */
--color-background       /* page background */
--color-foreground       /* body text */
```

Use these via Tailwind classes:

```html
<p class="text-muted-foreground">secondary text</p>
<div class="border-border">bordered box</div>
```

Do not hardcode hex values (`#6b7280`) in new code — use the token classes so
dark mode (if added later) works automatically.

## Components in use

All live in `src/components/ui/`. Installed via the shadcn-vue CLI.

| Component                                                      | Import                      | Use for                                 |
| -------------------------------------------------------------- | --------------------------- | --------------------------------------- |
| `Button`                                                       | `@/components/ui/button`    | all clickable actions                   |
| `Card`, `CardHeader`, `CardTitle`, `CardContent`, `CardFooter` | `@/components/ui/card`      | content panels, plan cards              |
| `Badge`                                                        | `@/components/ui/badge`     | plan labels, click counts, status chips |
| `Input`                                                        | `@/components/ui/input`     | form text inputs                        |
| `Label`                                                        | `@/components/ui/label`     | form field labels                       |
| `Alert`, `AlertDescription`                                    | `@/components/ui/alert`     | error and success messages              |
| `Separator`                                                    | `@/components/ui/separator` | horizontal/vertical dividers            |

## Adding a new component

```bash
# from frontend/
npx shadcn-vue@latest add <component-name>

# examples
npx shadcn-vue@latest add dialog
npx shadcn-vue@latest add table
npx shadcn-vue@latest add toast
```

Browse available components: https://www.shadcn-vue.com/docs/components

After adding, import from `@/components/ui/<name>`.

---

## Button `as-child` pattern

shadcn-vue's `Button` renders an `<a>` or `<RouterLink>` when you pass
`as-child` + a child element. Use this instead of wrapping a router-link
in a plain `<button>`:

```vue
<!-- correct -->
<Button as-child>
  <router-link to="/dashboard">Go to dashboard</router-link>
</Button>

<!-- avoid -->
<button class="..."><router-link to="/dashboard">Go</router-link></button>
```

## Conventions

1. **No `<style scoped>` in views** — use Tailwind utility classes only.
   Components inside `src/components/ui/` may keep their scoped styles (they're
   generated by the CLI and managed separately).
2. **No hardcoded colours** — use `text-foreground`, `text-muted-foreground`,
   `text-primary`, `text-destructive`, etc.
3. **Responsive prefix order**: mobile-first. Default = mobile, `md:` = desktop.
4. **Spacing scale**: prefer Tailwind scale values (`gap-4`, `px-6`) over
   arbitrary values (`gap-[17px]`).

## Upgrading

Tailwind CSS:

```bash
npm install tailwindcss@latest @tailwindcss/vite@latest
```

shadcn-vue components (re-add to overwrite):

```bash
npx shadcn-vue@latest add button --overwrite
```

shadcn-vue CLI itself is run via `npx` — no local install needed.
